# Аудит архитектуры — 25 октября 2026

Проверен локальный Front на базе коммита `1e20d8c`.
Вывод: фундамент выбран грамотно, полная смена архитектуры не нужна.
Запрещённых зависимостей слоёв и межстраничных импортов в исходной реализации
не обнаружено. При этом формального прохождения старого FSD-скрипта было
недостаточно: найдены проблемы контроля границ, владения асинхронным состоянием
и размещения бизнес-знаний. Перечисленные ниже проблемы исправлены локально.

## Исправления

1. **P1 — поздний ответ проверки личности мог восстановить состояние после выхода.**
   В `entities/session/model/store.ts` добавлена инвалидация поколений,
   объединение параллельных проверок и общая очистка личности/настроек.
   Проверка, начатая до сохранения профиля, не перезаписывает новое имя.
   Успешный выход и смена пароля очищают состояние даже при параллельной операции
   профиля. Выход завершает локальную сессию и при серверном 401/403; корневая
   оболочка переводит на вход после очистки личности. Отдельно устранена зависимость успешной аутентификации от доступности
   необязательных настроек; 401/403 при их получении остаётся отказом авторизации.
   Зафиксировано тестами с управляемым порядком ответов.

2. **P1 — публичный платёж мог показывать результат предыдущего токена.**
   Раньше `PayInvoicePage.vue` непосредственно загружал данные без инвалидации
   запроса при смене маршрута. Сценарий вынесен в локальный `model/usePublicPayment.ts`:
   GET отменяется, ответы и подтверждения привязаны к поколению и токену,
   данные плательщика сбрасываются при смене ссылки. Публичный транспорт вынесен
   в `entities/payment/api/public-invoice.ts`, cookies сессии исключены и для
   чтения, и для подтверждения. Проверено unit-тестами и браузером.

3. **P2 — завершение операции по старому счёту меняло интерфейс нового.**
   В `PaymentDetailPage.vue` добавлена проверка контекста операций и маршрута
   после асинхронных шагов. Позднее сохранение ссылки не очищает форму другого
   счёта и не показывает там сообщение об успешном сохранении. Браузерный тест
   задерживает POST, переключает счёт и проверяет сохранность новой формы.

4. **P2 — общий загрузчик не завершал жизненный цикл запросов.**
   `useAsyncData` теперь передаёт сигнал отмены и прекращает обновления после
   уничтожения владельца. Сигнал проведён через API и многостраничные справочники.
   `usePagedList` синхронно инвалидирует старый запрос при изменении фильтра,
   сохраняет debounce при сбросе номера страницы и не загружает данные после
   закрытия экрана. Тесты покрывают старый ответ во время debounce, восстановление
   последней страницы и disposal.

5. **P2 — `shared` содержал бизнес-справочники.**
   Периодичность платежей перенесена в `entities/payment/model/payment.ts`,
   события журнала — в новый слайс `entities/audit`. Журнал действий больше
   не использует тип сущности платежа для собственного списка событий.
   В shared оставлены общие инструменты форматирования и инфраструктура.

6. **P2 — архитектурный контроль имел пропуски.**
   Регулярное выражение заменено разбором TypeScript AST и Vue SFC.
   Теперь проверяются side-effect imports, реэкспорты, динамические импорты,
   импорты типов, несуществующие пути, публичные входы, собственные barrels
   и циклы исполнения. Публичные API требуют явных экспортов.
   Добавлено 11 тестов самого проверяющего инструмента, включая негативные
   примеры обходов и допустимый цикл исключительно стёртых типов.

7. **P2 — HTTP-клиент не соблюдал весь контракт `RequestInit`.**
   Теперь поддерживаются `Headers`, массив пар и объект заголовков;
   явно заданный Content-Type сохраняется. Ответ 204 больше не разбирается
   как JSON. Отказ устаревшего отменённого запроса не сбрасывает текущую сессию.

8. **P2 — часть capability URL оставалась в поставляемом access log.**
   Правило Nginx расширено на `/pay/` и `/api/v1/public/payments/`;
   прежние исключения для просмотра счетов сохранены. Runtime-проверка
   `nginx -t` в этом локальном проходе не выполнялась: контейнерный движок
   на машине недоступен. Серверная конфигурация не менялась.

9. **P3 — слабая профилактика регрессий и лишний код.**
   Включены `noUnusedLocals`/`noUnusedParameters`, типизированы метаданные роутов,
   удалён неиспользуемый клиентский paginator, защищён общий форматтер от
   некорректной даты. Добавлен CI workflow для checks/build без деплоя.
   Версии [checkout](https://github.com/actions/checkout/releases/tag/v7.0.1)
   и [setup-node](https://github.com/actions/setup-node/releases/tag/v7.1.0)
   проверены по официальным релизам и закреплены SHA.

- Изменения не отправлялись в GitHub и не деплоились; SSH не использовался.

## Принятые архитектурные решения

Отсутствие пустых `features`/`widgets` не считается дефектом:
[FSD допускает использовать необходимые слои](https://feature-sliced.design/docs/reference/layers).
Специфичная для страницы логика остаётся в её слайсе. Для публичного платежа
выделен page model, потому что там появился самостоятельный жизненный цикл,
требующий отдельных тестов. Внешние потребители используют
[публичные API слайсов](https://feature-sliced.design/docs/reference/public-api).

Большой глобальный CSS остаётся техническим долгом с низким приоритетом.
Его постепенное разделение следует делать по владельцам компонентов при
следующих изменениях интерфейса с визуальной регрессией. В этом аудите внешний
вид не переписывался. Генерация типов из OpenAPI также остаётся возможным
улучшением при дальнейшем росте API, а не обязательной зависимостью текущего проекта.

Это аудит архитектуры фронтенда и исправление подтверждённых дефектов,
не полная проверка backend-безопасности или поведения всех браузеров.
Правила продолжения разработки описаны в [архитектуре фронтенда](frontend-architecture.md).
